# 使用说明

## 进入与设置

启用插件后从 DSH 侧栏打开 **DeepSeek Servant**。模型、预设、原生工具和工作区权限沿用宿主；插件不能凭协作成员身份获取另一台电脑的权限。

- **Local**：选择保存业务数据的 Local 目录；任务工具执行工作区另行设置。
- **Git**：选择私有 `owner/repo` 与仓库根或子目录；运行环境需要 Python、Dulwich 与 urllib3，凭据使用同一环境中的 GitHub CLI 登录。日常内容通过 Git 协议传输。参见 [Git 说明](../PRIVATE_GIT.md)。
- **模型与预设**：选择实际可用模型及预设。后台 Auto 未显式指定模型时，沿用 DSS 前台明确选择的模型及推理强度；前后台均未指定时才使用宿主默认路由。不要把设置中的模型名称当成某条回复实际使用模型的证据。
- **每任务 Worker 席位**：填写非负整数；每个 Task 独立获得此容量，零表示不提供 Worker 席位。配置 2 席时，4 个有工作可执行的 Task 可各运行 2 个 Worker，合计最多 8 个，不共享同一个 2 席总池。

保存设置会尝试登记并开始后台参与。参与开关用于显式开始/退出；关闭页面不等于停止后台。Local 首次没有保存参与设置时默认参与；Git 不默认替用户开启远端参与。

## 对话与历史

普通查看、发送、读取附件与后台参与独立，不会仅因打开页面自动登记后台或唤醒执行角色。后台未参与时，消息可以先保存，并不保证此刻已有 AI 接单。

给 AI 的消息与成员间讨论有不同收件意图；人类间交流不自动等于执行授权。消息保存来源、设备及回复关系；历史按当前 UTC 保存日期和前后页回查；日期选择不改写消息的原始时间或来源时区；向上滚动接近当前页顶部会提前读取较早原文，并保持阅读位置。Local 日期定位当天末尾并在当天翻页；DSS-cah 日期定位所选日末尾，随后可继续跨日回查。页面草稿在发送结果未确认时保留原 ID；请核对原操作，不要把网络错误理解成“肯定未发送”后重复提交。

模式、协作范围和存储根分别绑定历史与草稿；切换模式不把旧正文写到新的目标。显示的实际模型元数据以已保存来源为准，未知就不伪造。

## 任务与成果

向 Foreground 说明目标、交付物及验收要求。短任务由前台直接处理；需要正式任务协作时，选择 P（Planner）或 O（Organizer 分派）路径。Planner 与 Worker 执行和验收成员工作；Organizer 负责 O 任务整体分派及验收。Recorder 保存长期资料，Helper 协助异常恢复。

任务页显示真实任务状态、成员、原生执行及结果路径。暂停、继续、取消和停止执行按对应控制入口操作；“请求已提交”不是“工具已经停止”。停止仍缺少原生确认时保留未知事实，不应通过刷新页面将其当成功。

任务整体完成后可查看已有结果；Foreground 独立通知用户，Recorder 同时整理，不要求用户阅读回执。新的完成变化提供轻量通知和本地未读标记；首次打开的历史完成任务不逐条弹出。清除本地标记不改写任务完成状态。

成果文本可读取，归档二进制可下载。只有实际保存的成果附件才能作为长期归档引用；源文件路径或外部链接本身不证明已有副本。

## 知识与归档

知识页用于查看记录、读取正文、直接保存技能正文及停用/退役。同一技能的并行编辑会合并互不重叠的修改；重叠冲突保留当前正文与用户草稿，由编辑者处理后重新保存，不生成候选文件。已有候选资料仍可查看，保存正文不改变既有停用/退役状态。并行任务生成的不同技能共同列入同一个共享目录；Git 按实际内容合并并发提交，确认后更新本端各角色可见的技能。旧技能的 scope、activeVersion 和验证事实保留；新技能按正式 `SKILL.md` 格式识别，普通 Markdown 不会全部变成可调用技能。

停用/退役让技能不再按当前目录加载，保留正文和历史来源。原生技能选择按实际角色范围处理，不把其他参与者或其他工作区旧技能默认全局启用。

Recorder 的归档和固定 Cleaner 的临时资料清理相互分工。Archives 中可打开成果附件，Local 可将已有完整记录原样导出到所选工作区；迁入的旧任务资料与旧已封存完整记录分别显示，不会把任务 JSON 当作完整记录或重新拼接摘要。

Local 设置中的「长期记录管理」提供独立确认入口：清理已结束任务记录、清理前台聊天、清空工作清单与缓存，以及查看和清理调试记录。预览、停止确认或写入结果不明时不会显示已成功；使用原操作重试，不另建重复删除。技能、知识及保留成果不随任务历史一起删除。

「搬家并应用」不同于单纯修改 Local 目录。明确确认后，插件只核停自己在 Local 中拥有的执行，Git 后台、连接、输入、读取和任务执行不受该搬家操作影响；搬迁技术记录及所选 Local 物理记录目录（包括仍需保留的升级原件），保留逻辑存储身份、原消息和恢复回执，再应用目录并按原参与设置接续。宿主原生会话日志和工程工作区不搬迁；目标已有记录不会被覆盖。未知结果保留原操作，关闭面板不会撤销已接纳的搬家。普通目录设置不自动搬走旧资料。

具体保留范围见 [RETENTION](../RETENTION.md)。

## 异常和旧数据

- 冲突：重读当前资料后再决定，不机械重放旧变更。
- 未知写入：保留原操作身份，核查是否已提交；不任意生成新消息或任务替代。
- Git 账号变化：已知旧账号不匹配会拒绝参与写入；缺少旧账号证据会报告无法核验，不自动重置实例。
- 旧任务迁移：保留原来源、等待状态及成果。无法确认执行归属的事项显示未解决，不自动标完成；按界面提供的实际接续/答复入口处理。
- 宿主能力不可用：以实际错误和能力诊断为准。



### 对话排版与资料链接

助手回复与 `.md` / `.markdown` 资料使用宿主提供的 Markdown 排版；“查看原文”可随时查看未改写的完整原文。用户输入及普通文本附件保持原文显示。图片在排版副本中显示为可主动打开的链接，不自动加载远程图片；代码示例保持原样。宿主没有 Markdown 能力时，保留完整原文显示，不要求升级宿主。

DSS 资料库链接使用库内逻辑相对路径，例如工具返回的 `archiveRecordsPath`（根任务为 `archives/<任务名加Task ID>/records.md`，子任务按任务树放在父档案的子文件夹中），由当前 Local 或 Git 资料库读取；它们不是本机磁盘地址。资料弹窗保留原文件下载，切换模式或资料库后不展示旧读取结果。

物理成果链接直接指向实际文件或目录，并在链接中携带原接入电脑的来源身份。打开只使用该地址和来源，不依赖任务 ID、任务历史或 Recorder 完成状态；清理任务历史不会改变链接目标。当前电脑与来源不符、路径不在所选工作区或文件不存在时会拒绝打开，不把其他电脑上的同名路径当作该成果。旧链接若只有裸路径、未携带来源，不会通过任务索引猜测原电脑。

角色使用 `dss_workspace_reference` 返回的完整链接引用物理成果；Recorder 记录其实际存放位置。已明确导入 DSS 档案的副本仍使用导入工具返回的逻辑路径，与物理原件区分，不猜造链接或改写旧会话原文。
