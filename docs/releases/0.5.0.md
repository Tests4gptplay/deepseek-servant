# DeepSeek Servant 0.5.0 候选说明

## 安装测试版 RC2

在 DSH 的 **插件 → 添加插件 → 包名或地址** 输入固定来源：

```text
github:Tests4gptplay/deepseek-servant#v0.5.0-rc.2
```

如同版 [Release](https://github.com/Tests4gptplay/deepseek-servant/releases) 列有 `.tgz` 资产，也可将该资产的下载地址填入同一个输入框，或下载后填写运行 DSH 的电脑上文件的完整绝对路径，无需解压。安装后启用插件。

包内版本显示 **0.5.0**，本测试候选由固定标签 **v0.5.0-rc.2** 标识。RC1 同样显示 0.5.0，升级时应核对安装来源变为 RC2。

**升级：** 先停止 DSS 任务并保留原数据。填写上面的 RC2 来源；若宿主提示已安装，先在插件管理中卸载该插件条目，再安装 RC2。保留 DSH 数据目录、Local 库及任务工作区，不执行记录清理或手工删除数据。按宿主提示重启；Desktop 需要时完整退出托盘进程再打开。升级后检查原设置、对话、任务记录与成果可读取。

**Web：** 在运行服务的环境停止对应 profile 后执行，再重新启动该 profile：

```sh
dsh plugin --profile web add 'github:Tests4gptplay/deepseek-servant#v0.5.0-rc.2'
```

使用 Release 资产时，将命令中的来源换成对应 TGZ 下载地址。Desktop 与 Web 分别管理安装。启用后从侧栏打开 DeepSeek Servant，详见[使用说明](../USAGE.md)。模型提供者与工具权限由 DSH 管理。

## Local / Git 统一协作

Foreground、Organizer、Planner、Worker、Recorder、Helper 使用 DSH 原生 Agent、Session、工具与 Jobs。Local 使用 SQLite 文件库，Git 在私有协作仓库使用远端树和 blob；任务、原子提交、角色交接与恢复采用统一接口。前台访问与本端后台参与分别管理。

## 前台与历史

- Foreground 每轮完成后使用新原生会话接续，带入最近六个完整往返原文；普通可见最终回复保存在共享对话中，并核对同轮显式发送以避免重复。
- 历史支持连续上滚和日期定位。Local 选日从当日末尾开始、限定当日；Git 选日先定位该日末尾，后续游标可跨日。
- AI 可按需全文搜索和按字符分页读取长文；保存的原文保持完整。工作清单与缓存的用途、路径及操作指南自动提供，正文按需读取。
- 已迁移的旧任务提供完整原记录入口；Local 可导出实际保存的全文。知识页展示项目事实、偏好正文及范围/来源，技能另有候选与停用操作。

## Local 记录管理

三类操作分别确认：**清理任务历史**、**清理前台对话**、**清理工作规划记录**。任务历史清理保留成果与其他任务引用的资料。取消 Task 只有在持久取消意图和精确生产者停止证据均成立后才可清理；状态保持原事实，不写成 complete。明确清理回执阻止旧 Task 重新执行或接受补充，后续业务使用新 Task。

**搬家并应用**先保存原操作、确认本插件拥有的执行停止，再复制核验技术记录和 Local 库并切换设置。原 scope、任务、命令、会话与消息身份保持；响应未知时核对原请求，重启后可继续核对。宿主原生日志不在此搬迁范围。

## 成果保全

Recorder 编写长期记录并读回验证；Cleaner 比较其所依据的资料及声明保留成果，发现晚到修改时保留资料并交回 Recorder 重核。成果附件按真实字节保存、核验和下载，任务间引用继续保留。清理回执关闭旧运行命名空间，前台长期规划、技能及诊断各按自身职责使用。

## 验证范围

源码回归、真实 SQLite、官方原生服务组合、受控模型/HTTP 和 React 组件测试分别记录。跨不同真实账户的公网联合协作尚未执行；受控场景不代表真实模型任务质量或所有用户设备已验收。最终结果须绑定同一提交、依赖与实际安装包；当前候选仍在统一验证中，不固定中途测试总数。
