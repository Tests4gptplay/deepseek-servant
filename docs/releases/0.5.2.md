# DeepSeek Servant 0.5.2 · 预发行候选

0.5.2 主要改进两件事：更容易找到任务和成果；后台执行中断后，能更准确地判断谁该继续接手原任务。

## 任务与成果更好找

- 「任务」和「成果档案」共用搜索框，支持按标题或任务 ID 查找。命中关联任务或档案时，也能在另一页找到对应记录。
- 有创建时间的任务按创建时间倒序显示。旧记录没有该字段时不补写虚构的创建时间。
- DSH 未提供目录浏览能力时，目录选择入口会明确提示不可用。

## 后台任务如何接续

- **Planner 负责把原任务推进到最终完成。** 任务未完成时，应当有实际交接，或能从任务状态核实接手人和触发条件。不能自行解决的执行卡点交给 Helper，不绕过恢复链直接上报前台。
- **处理缺少交接的静默轮次。** 只有原任务仍在运行、已受理的原生轮次已经结束，并且当前没有有效交接、合理等待或待执行的下一步时，才针对这条工作线请求 Helper 排查。仅凭没输出或等待时间长，不判断任务已停。
- **同一工作线换人，不重新投任务。** Worker 席位随工作线处理，不把旧会话仍在线或模型轮次结束当作业务交接。恢复时核对旧执行是否还持有工作；允许已失联的执行由后继从原进度接手，不伪造旧作业结算。
- **确认进展再宣布恢复。** Helper 优先处理具体卡点；常规办法无效时，才考虑重置相关 Host 状态。原任务取得可核对的新进展才算恢复；适用办法都无法推进时，才向前台说明阻塞。
