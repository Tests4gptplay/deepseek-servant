# DeepSeek Servant 0.5.2 prerelease candidate

0.5.2 makes tasks and archived results easier to find. It also helps DSS determine who should pick up the original task when work is interrupted.

## Finding tasks and results

- **Search both views.** The Tasks and Archives views share a search field. Search by title or task ID to find a task or its linked archive.
- **See newer tasks first.** Tasks with a known creation time appear newest first. DSS does not invent timestamps for older records.
- **Clearer folder picker feedback.** If DSH does not provide directory browsing, the picker reports that it is unavailable.

## Continuing interrupted work

- **Keep responsibility for the original task.** If a task is unfinished, Planner must hand it off or verify who will take over and what will trigger the next step. Execution blockers that Planner cannot resolve go to Helper, not directly to the foreground assistant.
- **Check for a missing handoff.** DSS asks Helper to investigate only when the task is still active, the accepted native round has ended, and there is no valid handoff, reason to wait, or pending next step. Silence alone does not mean work has stalled.
- **Replace the Worker, not the task.** Capacity stays with the same workline as a successor picks up saved progress. DSS checks whether the previous execution still owns the work and does not fabricate its final result.
- **Verify progress before declaring recovery.** Helper first addresses the specific blocker and considers resetting the affected Host state only as a fallback. Recovery requires verifiable new progress on the original task. Helper reports the blocker to the foreground assistant only if the applicable recovery options fail.
