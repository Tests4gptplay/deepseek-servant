# CAH 与 DeepSeek Servant：面向长期工作的 Agent 系统评述
### 任务连续性、技术路线纠偏与跨宿主迁移

**Review Report · 2026年11月12日**

## 摘要

Chat Agent Harness（CAH）与 DeepSeek Servant（DSS）围绕一个核心问题展开：**怎样让 AI 持续承担一项工作，在会话更替、运行中断和方案调整之后，仍然保留目标、继承成果，并推进到实际交付。**

CAH 通过真实工程任务积累了长期执行、角色接力、故障恢复和技术路线调整的运行经验。DSS 将同一架构路线迁移到 DeepSeek Harness（DSH）的原生执行环境，并进一步发展持续交互、多目标协作、记录管理与技能积累。两者共同呈现出一条具有实际成果支撑的 Agent 系统路线：**长期工作由任务与记录维系，执行者和承载环境可以更换，解决问题的方法可以根据证据调整。**[^A][^B]

本评述关注已经形成的能力、代表性案例、与相关研究及产品的联系，以及这条路线的应用和研究价值。项目运行成果、开发方向和研究判断分别说明。

| 核心优势 | 对实际工作的意义 | 代表性依据 |
|---|---|---|
| **长期任务连续性** | 跨会话、跨中断继承工作，减少从头解释与重新组织 | CAH 多日媒体制作任务 |
| **目标保持与路线纠偏** | 保留有效成果，同时根据新证据调整实现方法 | Viewer 的运行路线转换与成果验收 |
| **有生命周期的多 Agent 协作** | 将并行执行、前后接力和阶段判断组织为同一工作过程 | CAH 任务组织及持续执行案例 |
| **跨宿主迁移** | 将长期任务机制带到不同 AI 宿主与工具环境 | CAH → DSS 的工程实现 |
| **用户掌握工作积累** | 保存、检查和复用任务记录、工程成果与经验 | DSS 的记录、工作区与 Local／Git 能力 |

## 一、持续型 Agent 的价值，最终取决于能否承担完整工作

随着 Agent 从问答走向行动，评价重点正在发生变化。用户交给系统的，越来越多是需要持续处理的工程、研究、创作和事务，而不是一次回复就能结束的问题。

Grok Bot、Meta Muse 和 OpenAI dots 都体现了这一变化：它们强调持续工作、长期目标、记忆和后台执行，用户可以在任务推进期间继续交流，并在需要时参与判断。持续协作已经成为这一代 Agent 产品的重要方向。[^R7][^R8][^R9]

对于真实任务，持续协作意味着一系列具体要求：前一轮做出的成果需要被接手者找到；已经推翻的假设需要被记住；用户改变要求后，后续工作需要及时调整；执行环境发生故障时，系统需要辨认从哪里继续；最终交付还需要对应最初的目标。

**CAH/DSS 的关注点正是这些工作之间的连接。**

模型能力决定了一个执行者能够理解和完成什么，任务组织则影响这些能力能否在较长时间内累积为一个完整结果。CAH/DSS 的系统价值，主要体现在后者：让多次推理、多次执行和多个角色之间形成可延续、可检查、可调整的工作过程。

这也是长期 Agent 与普通工具调用演示之间的重要区别。对使用者而言，有价值的是系统留下了什么成果、怎样接续已有工作，以及遇到困难后能否继续朝原目标前进。

## 二、CAH 与 DSS：同一架构路线的两项工程实践

CAH 是这条路线的早期实现。其公开版本已经包含持久任务记录、可替换的 Worker、任务监督、执行能力和经验复用。DSS 则明确继承 CAH 的 Agent 设计体系，通过 DSH 原生能力实现持续任务执行。[^A][^B]

因此，对二者最合适的理解是：

> **CAH 提供原始架构与长期运行经验；DSS 提供跨宿主迁移、原生集成和进一步产品化的实践。**

任务树、多角色分工、执行接力、阶段验收和异常恢复，在 CAH 中已经构成相互关联的工作体系。DSS 在此基础上适配新的模型会话、工具和作业环境，继续扩展持续前台与协作范围。它继承的是一套完整的任务组织思想。

从高层看，这条路线的设计原则可以概括为：**任务目标、工作记录和成果长期保存，AI 会话作为可替换的执行载体，业务判断与运行协调各自承担明确职责。** 这一原则让任务的存在不依赖某一条会话始终在线，也为更换宿主和执行环境提供了基础。

这种继承关系也解释了 DSS 的技术意义。它既是一项可使用的助理插件，也是一项架构迁移实践：原先在 ChatGPT、Git 和本地执行环境中形成的长期工作机制，能够在 DSH 原生环境中重新落实。

## 三、长期任务连续性：跨越中断，仍然走到成果验收

### 多日任务比单次运行时长更接近实际需求

真实工作通常不是一段没有间断的计算。它可能包含等待、用户决策、工具执行、检查、返工和恢复。持续型 Agent 的重要能力，是在这些状态之间仍然保留同一项工作的目标与进展。

根据项目方留存的任务提交和最终验收记录，CAH 的一项完整媒体制作任务，从 **2026年10月17日**启动，到 **10月22日**完成 Planner 初稿验收，历时约 **4天11小时**。期间经历了执行接替、运行恢复和用户改策，最终形成约 **3分32秒的完整 MV 初稿**，并保留源工程及验证材料。[^C]

这项案例的意义在于，任务并未因执行者变化或中断而失去连续性。前面已经完成的工作继续成为后续制作的基础，用户提出的新方向也进入原来的任务过程，最终形成了明确的阶段性交付。

**中断恢复本身就是长期任务能力的一部分。** 对这类系统，任务能否完成、恢复需要多少人工操作、需要重做多少工作，是几个可以分别观察的维度。把它们分开记录，才能看清系统到底承担了哪些工作。

### 连续性的收益来自工作积累

长期任务最容易浪费的资源，往往不只是模型调用，还包括已经完成但没有被正确继承的工作：重新定位文件、重新理解约束、再次尝试失败路线，或者重新确认一个已经得到答案的问题。

CAH 的案例体现了对这些损耗的处理方向：保留成果与判断依据，让后继执行围绕尚未完成的部分继续推进。对于跨日工程和创作任务，这使 AI 的投入有机会形成累积，而不是随着会话结束重新归零。

Anthropic 的长期 Agent 工程研究同样将跨上下文接续视为关键问题，通过清晰的工作记录和可接手的工程状态，使新的会话能够继续增量开发。CAH 的多日实践与这一研究方向相呼应，并将问题放到了包含真实工具、执行故障和用户调整的完整任务周期中。[^R2]

## 四、Viewer 的成功：保留成果，同时改变解决问题的路线

长期执行的另一项关键能力，是避免让某个技术子问题逐渐替代原始目标。

工程任务经常出现这样的情况：最初要完成的是一个可使用的工具，后来却把大量精力集中在修复某个接口或维持某种实现方式。即使当前路线的收益不断下降，系统仍可能沿着它继续深入。

CAH 的 Viewer 案例提供了一个积极的对照。

### 从历史方案走向新的可用实现

在 2026年9月28日的 Viewer/Cook 任务中，系统先分别推进资源构建与 Viewer 基础，再进行集成。面对实际加载、运行和画面问题，后续工作重新评估了技术路径，最终形成了不同于历史实现的独立运行方案。

整个过程中，有效的输入和工程成果得以保留，加载与运行方式则根据证据调整。任务最终以实际原生画面和交互效果通过验收，从启动到 P1 接受共用时 **5小时1分30秒**。[^A]

| Viewer 中的实际表现 | 对长期 Agent 的意义 |
|---|---|
| 历史实现作为参考，新任务重新判断适用路线 | 经验可以复用，同时保持方案调整空间 |
| 技术操作成功后，继续检查真实画面和交互 | 将过程进展对应到用户需要的实际结果 |
| 原路线受阻后，转换运行与集成方式 | 围绕目标寻找有效路径 |
| 保留已有有效成果，完成新的集成与验收 | 改路能够建立在前序工作的基础上 |

这是一项完整的工程成功：**系统既能够继续工作，也能够改变继续工作的方式。**

### 生命周期轮动与阶段判断的价值

CAH 中的角色接力与阶段验收，为后继重新面对原目标、已有成果和失败证据提供了机会。执行者可以更换，但任务要求和有效积累继续保留。这使长期协作同时具备“继承”与“重估”两种能力。

Viewer 展示了这种组织方式下实际发生的有效改路。它所体现的价值，是降低局部技术路线长期占据整个任务的机会，使系统能够根据真实结果修正判断。

这一问题也有明确的研究对应。Sakana 的 *The Agentic Scientist* 将长期探索中的局部改进倾向视为重要问题，并通过跨 Agent 编排、阶段检查和结果汇总组织较长的研究过程。其关注点与 Viewer 的案例相通：**系统需要积累进展，也需要保持重新判断方向的能力。**[^R5]

对 CAH/DSS 而言，这是一项值得继续深化的优势：长期记忆保存已经取得的知识，角色协作和阶段评审使这些知识能够被重新解释和使用，而不是把某次推理中的假设永久固化。

## 五、从 CAH 到 DSS：架构可迁移性的实际意义

### 更换承载环境，保留长期工作的组织方式

CAH 与 DSS 使用不同的执行入口。前者在 ChatGPT、Git 与本地工具环境中组织任务，后者通过 DSH 原生 Agent、Session 和 Jobs 承担工作。DSS 的公开资料还记录了 Local 与 Git 两种模式、模型与工作区配置，以及持久记录和任务控制能力。[^B]

这种变化具有重要意义：**长期任务能力能够从原始执行通路迁移到另一套宿主，而任务协作的核心原则继续成立。**

DSS 的原生验收记录已经覆盖两代 Worker 接力、真实文件与作业执行、Planner 验收，以及进程终止后的任务恢复。在该次测试中，Agent、Session、文件工具、Jobs 和存储使用实际 DSH 服务，模型响应与 Git API 使用受控对端；恢复后继续处理原工作，并完成最终成果核对。[^B]

| CAH 提供的实践 | DSS 提供的进一步依据 |
|---|---|
| 长期任务与多角色协作 | 同类工作机制进入 DSH 原生环境 |
| 会话更换后的工作接续 | 原生 Agent／Session 生命周期下的接续 |
| 中断后保留任务与成果 | 实际宿主进程终止后的恢复验证 |
| Git 支撑持久工作 | Local／Git 按不同部署需求承载任务 |
| 工具与工程环境接入 | 使用 DSH 原生工具和 Jobs 完成执行 |

这些材料表明，CAH/DSS 的价值能够超出某一个聊天产品、账号条件或特定浏览器入口。最初采用何种执行通路，是工程实现的选择；长期任务怎样保存、接续和验收，则属于可复用的系统能力。

### 可迁移性带来的用户价值

对使用者而言，可迁移性意味着长期积累有机会继续使用，而不必因为更换模型或宿主就重新组织全部工作。

对开发和研究团队而言，它意味着可以保留已有任务组织方式，结合新的执行环境接入专业工具，并比较不同模型、宿主和资源配置下的任务效果。

DSS 的公开资料已经记录 Windows 原生任务验证和 Linux 早期功能基线。跨操作系统的具体适配范围由相应宿主与工具环境承载；CAH→DSS 的迁移则为跨 AI 宿主的架构复用提供了直接依据。[^B]

### 跨系统协作是自然的延伸方向

在这条架构路线下，CAH 与 DSS 进一步互通具有明确的技术动机：让适合不同环境的执行端参与同一项长期工作，并将成果交回相应的任务验收过程。

这一方向的价值，在于结合不同系统的模型、工具和运行环境，同时延续共同的目标与工作记录。当前阶段，可将其作为建立在两套实现之上的后续扩展方向。

## 六、与 Grok Bot、Muse、dots 的关系：共同需求，不同的价值侧重

Grok Bot、Muse 和 dots 的公开能力说明，持续助理正在从“回答问题”向“长期承担工作”发展。它们分别强调 Agent 团队、个人长期目标、后台执行和跨应用协作。[^R7][^R8][^R9]

CAH/DSS 与这些产品处于相近的问题空间，但具有鲜明的工程取向。

| 产品或路线 | 公开强调的方向 | 与 CAH/DSS 的对照意义 |
|---|---|---|
| **Grok Bot** | 持续工作的 Agent 团队、工具与应用操作 | 多执行者如何分工、接力和共同交付 |
| **Meta Muse** | 个人长期目标、记忆和持续行动 | 长期交互如何连接到持续任务 |
| **OpenAI dots** | 后台工作、云端执行和跨应用协作 | 用户离开对话后，任务怎样继续推进 |
| **CAH/DSS** | 持久任务、执行接替、成果验收与宿主迁移 | 用户怎样掌握长期工作，并让它在不同执行条件下延续 |

从这些公开定位与项目资料可以看出，厂商产品着重提供整合后的持续服务体验；CAH/DSS 的突出价值，则体现在**用户能够掌握工作记录、结合自己的工程环境、检查任务过程，并调整或迁移执行方式**。

对需要专业软件、长期项目资产和可追溯工作过程的使用者，这些属性具有直接意义。它们使持续 Agent 能力进入已有工作环境，而不仅是增加一个新的聊天入口。

这类比较最适合落到具体任务：是否完成目标、是否及时改路、需要多少次人工纠偏、重复做了多少工作，以及交付物是否便于继续使用。CAH 的 Viewer 和多日任务案例，已经提供了可以围绕这些问题讨论的实际材料。

## 七、发展时间线与独立实践的前瞻性

CAH 的早期研发记录可以追溯到 **2026年9月17日**；**9月20日**公开的 v1.0.4 已包含持久任务记录、可替换 Worker 和任务监督等能力。DSS 随后沿这条路线进入 DSH 原生实现和公开发行。[^D][^A][^B]

作为产品发展背景，Muse 于 **9月8日**公开，dots 于 **9月29日**公开。CAH 的早期研发与 Muse 处于同一时期，其公开发行早于 dots 九天。[^R8][^R9]

| 时间 | 项目或产品节点 | 对评价的意义 |
|---|---|---|
| **2026年9月17日** | CAH 留存的早期连续性设计与实现记录 | 形成具体的长期任务研发路线 |
| **2026年9月20日** | CAH v1.0.4 公开发行 | 将持续任务机制交付为公开工程 |
| **2026年9月29日** | OpenAI dots 公开 | 持续型助理进入更广泛的产品化阶段 |
| **2026年10月** | DSS 的 DSH 原生实现与公开交付 | 将既有架构迁移到新的宿主体系 |

这条时间线支持对 CAH/DSS 的一个重要评价：**它是在持续型 Agent 集中产品化的早期阶段，就已经形成协议、实现和实际任务实践的独立工程路线。**

其前瞻性同时体现在两方面：较早识别长期任务的连续性问题，以及随后通过真实工作不断发展解决办法。时间先后提供研发进程的依据，任务成果和宿主迁移则提供技术价值的依据。

## 八、放入研究脉络：CAH/DSS 的贡献集中在系统层

长期 Agent 研究已经积累了任务规划、外置记忆、工具执行、持久运行和多 Agent 协作等方法。CAH/DSS 的特点，是把这些问题放入一个完整工作过程，并用长期工程任务检验其接续、纠偏和交付效果。

| 相关研究 | 主要研究内容 | 与 CAH/DSS 的联系 |
|---|---|---|
| **Magentic-One** | 多 Agent 任务规划、进度记录和停滞后的重新规划 | 对照长期任务中的组织、评审与改路 |
| **Effective Harnesses for Long-Running Agents** | 跨上下文窗口的增量执行与工程接续 | 对照会话替换后怎样继续已有工作 |
| **Scaling Managed Agents** | 持久会话记录、运行循环和执行环境的分离 | 对照任务状态与可替换执行环境的关系 |
| **Letta Context Repositories** | 文件式记忆与 Git 版本化管理 | 对照长期记录的保存、读取与复用 |
| **The Agentic Scientist** | 跨 Agent 编排、阶段验证和长程探索 | 对照长期任务中的目标保持与路线重估 |
| **Towards a Science of Scaling Agent Systems** | 协作结构、任务特点与多 Agent 收益的关系 | 对照什么工作适合并行、接力和集中评审 |

上述工作分别从组织、记忆、执行环境和评估角度讨论相关问题。Microsoft 的 Magentic-One 明确包含进度跟踪和重新规划；Anthropic 讨论跨会话接续及运行组件分离；Letta 将长期上下文组织为可版本化的文件；Sakana 与 Agent scaling 研究则将协作方式和任务结构纳入效果分析。[^R1][^R2][^R3][^R4][^R5][^R6]

在这一研究脉络中，CAH/DSS 最有辨识度的部分，是三种能力的结合：

**第一，长期工作能够接续。** 任务身份、有效成果和判断依据可以跨执行者变化继续使用。

**第二，接续过程中能够重新判断。** 保留进展的同时，允许根据真实证据修正假设、改变方案。

**第三，工作组织方式能够迁移。** CAH 与 DSS 的不同宿主实现，使持续任务机制获得了跨环境的工程依据。

这三点形成了一个相互支持的整体。持久化让换代有依据，换代与评审为重新判断提供机会，明确的职责分离则为迁移和扩展提供条件。

## 九、应用价值：让工程资产和长期经验持续发挥作用

CAH/DSS 的价值，在以下类型的工作中尤其容易体现：

| 工作类型 | 常见需求 | CAH/DSS 对应的价值 |
|---|---|---|
| **软件与工具开发** | 多阶段实现、反复验证、持续修订 | 保留工程进展，围绕验收要求持续推进 |
| **三维与媒体制作** | 专业工具链、素材积累、效果检查 | 将工具执行、实际输出和方案调整连接起来 |
| **研究与实验流程** | 长作业、结果比较、跨日接续 | 保留实验过程与结果，支持后续判断 |
| **多目标项目协作** | 多条工作线、阶段汇总、目标变更 | 在分工执行中维持共同目标和成果归属 |

其中，Viewer 和媒体制作提供了直接案例；研究实验和跨系统协作则是值得继续拓展的应用方向。

对于长期项目，记录的价值还会延伸到任务结束之后。已有成果、失败经验和经过验证的方法，可以成为后续工作的输入。DSS 的记录管理与技能积累能力，为这种复用提供了产品基础。[^B]

从使用者角度，这意味着系统的价值能够随项目积累增长：工作完成后留下的，不只是一次答复，还有能够继续使用的工程资料和经验。

## 十、综合评价与后续发展价值

### 工程价值：已有成果支撑

CAH 的 Viewer 与多日任务表明，这套系统能够承担包含真实工具、实际产物、反复检查和方案调整的较长工作。DSS 的原生实现进一步说明，相同架构原则能够进入不同宿主的会话和作业体系。

这些证据共同支持一个明确判断：

> **CAH/DSS 已经形成了有实际运行积累的长期 Agent 系统，其价值体现在完整工作的组织、接续、纠偏和交付。**

### 研究价值：问题具体，证据可积累

值得进一步研究的方向，包括生命周期轮动对目标保持和路线选择的影响、中断后的工作继承、不同协作方式的成本，以及跨宿主任务交接。

评价这些方向，可以继续围绕成果质量、人工纠偏、重复劳动、恢复后的有效进展和总成本展开。其目标是把现有案例体现的优势，转化为能够在更多任务中重复观察的结果。

相关 scaling 研究也提示，协作收益需要结合任务结构理解。CAH/DSS 已有的实际任务，为研究并行执行、前后接力和阶段判断之间的组合提供了具体基础。[^R6]

### 产品价值：持续工作与用户掌控相结合

CAH/DSS 的鲜明取向，是让用户既能委派长期工作，也能保留对工作积累和执行环境的掌握。

持续前台提供交流入口，长期任务组织负责推进工作，记录与成果成为可继续使用的资产，宿主迁移则拓展了模型与工具选择的空间。对于希望把 AI 接入真实工程环境、持续积累项目知识的用户，这是一组具有实际吸引力的能力。

### 总体结论

**CAH 与 DSS 最值得关注的成果，是将“任务持续存在、执行者可以替换、方法可以纠偏、宿主可以迁移”组织成了一条有工程证据支持的实践路线。**

CAH 提供了多日任务完成与技术路线调整的案例；DSS 将这套经验迁移到新的原生 Agent 环境，并继续发展持续协作能力。两者共同展示了长期 Agent 的一种重要方向：让 AI 的单次能力通过持久任务和有效协作不断积累，最终成为可以交付、检查和继续使用的工作成果。

**这使 CAH/DSS 的价值超出了单个插件功能，体现为一种面向长期工作的 Agent 组织方式，以及围绕它形成的工程经验、可迁移性和进一步研究空间。**
