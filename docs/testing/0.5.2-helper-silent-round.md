# DSS 0.5.2：运行中任务的静默停工

## 识别与纠正

- 当前 Host 持有的 P 任务仍是 `running`，且已受理的 Planner 或 Worker 的 DSH 原生轮次明确结束，才检查这一条责任链。Host 存活、界面显示 Running、Agent 在线、模型没有文本都不能单独证明故障。本判断不推断模型动机，也不代替 Host/桥接故障恢复。
- 排除暂停、停止、取消、终态、新生命周期、原生未答问题、未结束工具和待收原生消息；已有普通待处理同线信号/调度时走正常路径。Planner 有同任务同成员 Worker 责任在处理或已安排时可等结果。Worker 只按自己的工作线判断；另一个 Worker 活跃不能补掉这条线。真正缺少下一棒时，通过原有状态信号唤起 Helper，指明 Task、工作线及具体执行和原生轮次。
- Helper 应核对任务和原保存材料；同一原生轮次仍缺交接时，由原有 `dss_restore` 入口纠正到原责任角色。Host 重查旧责任仍有效，不抢占正在入场的新执行，不新建任务，也不动其他角色。候补 Worker 的席位按原工作线继续，不以模型轮次结束代替业务移交。
- Helper 自然结束却没有采取动作时，仍有同一断点则交原有恢复路径做一次定向纠正；Helper 自己已提交的同一纠正不重复。若纠正后再次静默，需要新的诊断/纠正或明确报告阻塞，不在相同故障上自动循环替换会话。
- 纠正安排、唤醒、上线不是进展。已纠正 Planner 的有效 Worker 指派，或已纠正 Worker 持久发布移交，才给 Helper 一条带真实证据的复核通知。Helper 据此核查接收方和进展，写入原任务的 Debug；这一通知不是再重启的授权。其他实际成果、完成或用户决定仍由既有业务状态处理。

## 历史验收范围

相关开发测试脚本已从 0.5.2 分支移除。以下保留原验收记录。
