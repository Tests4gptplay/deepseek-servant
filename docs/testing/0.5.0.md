## 业务场景

### 01 · Local：补充要求后取消

**环境：Linux，RC5，实际 DSH，Local 模式。**

任务因缺少数字而等待。随后补充 `[4,7,11]` 并要求继续等待，最后取消。

原任务读取了补充内容；原文保留，最终状态为取消并归档，未执行计算。

- 共 38 次模型请求、回复及确认，其中 4 次为基础连通测试。
- 四次服务接收回执分别为 **39 / 49 / 24 / 30 毫秒**。
- 这些数值只表示服务接收，不代表前台响应或任务完成耗时。

### 02 · DSS-cah （实验性）

**环境：Linux，RC5，两套实际 DSH，隔离仓库、真实 Git 协议。**

模型在受控 Git 环境中实际处理请求；该场景不包含 GitHub 公网延迟。

任务组合为 **O → 两个 P → 各一个 W**，另有独立 **P → W** 质量检查。

**订单与库存**

| 输入 | 内容 |
| --- | --- |
| 订单 O1 | A × 3，B × 2 |
| 订单 O2 | A × 4，C × 1 |
| 订单 O3 | B × 5，C × 2 |
| 可用库存 | A：8−1；B：4−1；C：2−0 |
| 质量检查 | 38 件中有 3 件不合格 |

**实际交付**

- 需求：A **7**、B **7**、C **3**，共 **3 单 17 件**。
- 可用：A **7**、B **3**、C **2**。
- 缺口：A **0**、B **4**、C **1**。
- 合格：**35 / 38**。
- 4 个任务完成，两份成果在双方读回一致；独立计算核对通过。

共 **85** 次实际模型请求、回复及确认（70 + 15），未记录工具错误或测试桥超时。

### 03 · Windows：Local 与 DSS-cah（真实 GitHub）

**环境：Windows，RC5；固定合成消息，不调用 AI，也不创建后台计算任务。**

保存正文、独立历史查询及页面读回一致。

| Local 消息保存 | 481 毫秒 |

本项覆盖消息存储与读取；未包含多角色任务或重启恢复。表中为独立操作的单次观测。

统计来自隔离测试环境；请求耗时存在重叠，不代表用户等待时间。
